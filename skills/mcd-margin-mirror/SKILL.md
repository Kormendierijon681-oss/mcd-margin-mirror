# 麦麦毛利镜

## 做什么

把一份麦当劳订单拆成门店层面的成本结构，估算毛利与毛利率，并给出盈亏平衡让利率。

一句话卖点：**你省下的钱，减的是营收，不是成本。**

## 什么时候用

- 用户想知道"我这单门店赚了多少"
- 用户想比较不同优惠券方案下，门店毛利怎么变
- 用户问"折扣打到几折门店就不赚钱了"

## 什么时候不要用

- **没有成本参数时不要用。** 缺失 `food_cost_ratio` / `labor_ratio` / `occupancy_ratio` / `royalty_ratio` 就直接告诉用户需要填，不要用"行业经验值"编造。
- 用户只要"怎么点最便宜" → 那是省钱类工具，不是本技能。
- 用户要下单 → 本技能只做分析，不调用 `create-order`。
- 计算结果要用在商业决策、投资、合同上 → 明确告知这是估算，不可作为依据。

## 执行步骤

1. **取数**：调 `query-meals` 拿原价；依次调 `auto-bind-coupons`、`available-coupons`、`query-my-coupons`、`query-store-coupons` 四路取券；调 `calculate-price` 拿券后实付。
2. **算**：调用 `scripts/demo.py` 或 `src/estimator.py`，按键入参数确定性计算。**不要口算，不要估。**
3. **讲**：把结果讲成人话 —— 省了多少、门店这单赚（或亏）多少、折扣再深一点会怎样。
4. **标**：每次输出都必须带上免责声明：结果为估算，非官方数据，不构成经营建议。

## 关键建模规则（改动前必读）

```
固定类成本（食品/人工/房租/其他）按【原价合计】计 —— 不因用券而减少
变动类成本（特许权费）按【券后实付】计 —— 跟着实付走
```

如果把所有成本都按实付比例摊，毛利率会恒定不变，那是错的。
