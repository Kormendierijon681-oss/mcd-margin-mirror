# mcd-margin-mirror · 麦麦毛利镜

> 你花 47 元点了一餐，用券后只付 21.9 元。
> **这单门店赚了多少？**
> 麦麦毛利镜把餐饮经营者的成本视角，搬到你自己的麦当劳订单上。

---

## ⚠️ 先读这段，再决定要不要用

1. **本工具不含任何品牌的真实成本数据。** 所有成本率必须由使用者自己填写（来自你认可的公开财报口径、行业研究，或你自己的经营数据）。不填就用不了 —— 这是刻意的。
2. **输出是结构化估算，不是官方数据，不构成经营建议。** 别拿它去论证任何商业结论。
3. `sample_data/` 里的菜单与参数**全部为虚构占位符**，只用于演示计算流程。
4. 项目灵感来自餐饮经营中的「成本率摊分」常识，与麦当劳官方无关。

---

## 它解决什么问题

所有人都知道"用券能省钱"，但很少有人想过另一半：

> **你省下的钱，减的是门店的营收，不是门店的成本。**

薯条的进货价不会因为你用了一张券就变便宜，店员的工资也不会。
所以优惠力度越大，门店这一单的毛利掉得越陡 —— 甚至会变成亏的。

麦麦毛利镜做的事：

1. 通过麦当劳 MCP 取当前门店的实时菜单价格与可用券；
2. 用 MCP 的 `calculate-price` 得到券后实付；
3. 按使用者提供的成本结构，把这一单拆成食品/人工/房租/特许权费/其他；
4. 算出估算毛利、毛利率，以及**盈亏平衡让利率**（超过这个折扣，这一单门店不赚钱）。

## 快速开始

```bash
git clone https://github.com/<你的用户名>/mcd-margin-mirror.git
cd mcd-margin-mirror

# 1) 离线演示（不需要 MCP Token，用虚构样例数据跑通全流程）
python3 scripts/demo.py
open docs/demo.html

# 2) 自测断言
python3 scripts/selftest.py      # 16 passed, 0 failed
```

要求：Python 3.9+，**零第三方依赖**（只用标准库）。

## 接真实数据

把你的成本参数写进 `sample_data/params_sample.json`（或另建文件）：

```json
{
  "food_cost_ratio": 0.32,
  "labor_ratio": 0.18,
  "occupancy_ratio": 0.12,
  "royalty_ratio": 0.05,
  "other_ratio": 0.06,
  "source": "填写你的口径来源",
  "note": "填写口径说明"
}
```

字段含义（`src/cost_model.py` 有完整说明）：

| 字段 | 类型 | 按什么计 |
|---|---|---|
| `food_cost_ratio` | 固定 | 原价营收 |
| `labor_ratio` | 固定 | 原价营收 |
| `occupancy_ratio` | 固定 | 原价营收 |
| `other_ratio` | 固定 | 原价营收 |
| `royalty_ratio` | 变动 | 券后实付 |

**固定类不因顾客用券而减少，变动类跟着实付走。** 这个区分是本工具算得准不准的关键。

## 目标用户

- 想弄明白"优惠到底谁在买单"的普通消费者
- 餐饮从业者：想给学生/同行讲清楚成本率与让利率的关系
- 对 MCP + 确定性算法组合感兴趣的开发者（可参考本项目的分层设计）

---

## 设计原则：取数交给 MCP，算术交给代码，表达交给 Agent

| 角色 | 职责 |
|---|---|
| 麦当劳 MCP | 实时菜单、价格、券、核价 |
| `src/estimator.py` | 确定性成本拆解与盈亏平衡计算 |
| WorkBuddy Agent | 理解需求、归一化数据、把结果讲成人话 |

为什么不让大模型直接算：成本拆解是带约束的确定性算术，让模型口算会飘。同一个输入必须永远得到同一个输出 —— 可测试、可复现、可断言。

## 离线可复现
